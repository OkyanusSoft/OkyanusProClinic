# 🦷 نظام إدارة عيادة د. عبدالله الشرفي لطب الأسنان

### OkyanusProClinic — منظومة عيادة أسنان متكاملة باللغة العربية

**نظام تشغيل كامل للعيادة: من تسجيل المريض ودخوله غرفة العلاج، حتى الفوترة والطباعة والمتابعة — على قاعدة بيانات MySQL مركزية.**

[React](https://react.dev) · [TypeScript](https://www.typescriptlang.org) · [Vite](https://vitejs.dev) · [Tailwind CSS v4](https://tailwindcss.com) · [Express](https://expressjs.com) · [MySQL](https://www.mysql.com)

</div>

## 📋 نظرة عامة

نظام احترافي متكامل لإدارة عيادة أسنان، مصمم بالكامل باللغة العربية (RTL) بهوية بصرية خاصة. يغطي دورة العمل السريرية والإدارية والمالية من الطرف إلى الطرف، مع نظام صلاحيات دقيق يعزل رؤية كل دور، وقاعدة بيانات MySQL مركزية مشتركة بين جميع الأجهزة.

### ✨ أبرز ما يميز النظام

- **١٤ شاشة متكاملة** تغطي التشغيل اليومي، العمل السريري، المالية، والإدارة
- **محطة عمل سريرية للدكتور** بمؤقت حي، ٨ تبويبات، وفوترة تلقائية عند خروج المريض
- **خريطة أسنان تشريحية** بأسنان حقيقية (تاج + جذور) وترقيم FDI واضح
- **نظام عودات ومتابعة ذكي** يُنشأ تلقائياً عند إنهاء الجلسة باقتراحات ذكية
- **نظام صلاحيات بمصفوفة** — الطبيب يرى مرضاه فقط، والسكرتارية ترى ما مُنحت
- **قاعدة MySQL مركزية** مع مزامنة حية ومؤشر اتصال، وتخزين محلي احتياطي تلقائي
- **طباعة A4 احترافية**: فواتير، روشتات، ملف المريض، كروت هوية، وكشوف مواعيد
- **تعدد العملات** — الأساس ريال يمني مع تحويل فوري لأي عملة

## 👥 الأدوار والصلاحيات

يعزل النظام رؤية كل دور عبر نظام صلاحيات بمصفوفة، مع **نطاقي رؤية** إضافيين:

| الدور | نطاق الرؤية الافتراضي | أبرز الصلاحيات |
|-------|----------------------|----------------|
| **المدير** | كل شيء | جميع الشاشات + المستخدمون + الإعدادات |
| **الدكتور** | مرضاه ومواعيده فقط | محطة العمل، المرضى، المواعيد، الروشتات |
| **السكرتارية** | كامل السجل | المواعيد، المرضى، الفواتير، العودات |
| **المساعد الطبي** | كامل السجل | المواعيد، محطة العمل (مساعدة)، المرضى |

### نطاقا الرؤية (قابلان للتوسيع من مصفوفة الصلاحيات)

- **كل المرضى** `scope_all_patients` — بدونها يرى الطبيب مرضى مواعيده وجلساته فقط
- **كل المواعيد** `scope_all_appointments` — بدونها يرى الطبيب جدول كرسيّه فقط

## 🛠️ التشغيل والإعداد

### ١) الواجهة (React + Vite)

```bash
npm install
npm run dev        # وضع التطوير
npm run build      # إنتاج البناء في dist/
```

### ٢) قاعدة البيانات المركزية (MySQL) — اختياري

بدون الخادم يعمل النظام على **التخزين المحلي** تلقائياً. لتفعيل القاعدة المركزية:

```bash
# أ) إنشاء القاعدة والجداول
mysql -u root -p < server/schema.sql

# ب) تشغيل الخادم
cd server
npm install
cp .env.example .env     # عدّل بيانات الاتصال
npm start                # يعمل على http://localhost:4000
```

الواجهة تكتشف الخادم تلقائياً ويتحول مؤشر الشريط العلوي إلى **«MySQL متصل»** وتُزامَن كل التغييرات فوراً. إن توقف الخادم تعود الواجهة للتخزين المحلي دون فقد بيانات.

لتغيير عنوان الخادم:
- متغير البناء `VITE_API_URL`، أو
- `localStorage.setItem("dental-api-url", "http://خادمك:4000")`

### ٣) النسخ الاحتياطي

من **الإعدادات العامة ← البيانات والنسخ**: تصدير/استيراد قاعدة البيانات كاملة كملف JSON.

## 🖨️ منظومة الطباعة (A4)

كل الطباعة موحّدة على مقاس **A4** عبر بوابة طباعة مستقلة تطبع الورقة فقط دون الواجهة:

| المستند | من أين |
|---------|--------|
| الفاتورة (بترويسة العيادة) | الفواتير ← زر الطابعة |
| الروشتة الطبية (مع تنبيه الحساسية) | ملف المريض / محطة العمل |
| الملف الطبي الكامل للمريض | سجل المرضى ← زر الطابعة |
| كشف مواعيد اليوم + المتابعات | المواعيد ← «طباعة كشف اليوم» |
| التقارير (٧ أنواع) | مركز التقارير ← «طباعة التقرير» |
| **كروت الهوية والمواعيد** | بطاقات ٨٥.٦×٥٤ مم على A4 مع خطوط قص |

### أنواع الكروت

- **كرت المريض** — وجه تعريفي + ظهر بباركود وشريط حساسية
- **كرت الموعد** — يُطبع للمريض عند الحجز
- **كرت الرجوع** — موعد المراجعة القادم

## 💰 تعدد العملات

العملة **الأساسية** هي الريال اليمني (YER) — تُحفظ بها جميع السجلات. يمكن إضافة عملات وتعيين أيها **افتراضية للعرض**، فتحول المبالغ لحظياً بسعر الصرف المحدد. الإدارة من شاشة **العملات**، والاختصار من **الإعدادات العامة ← الفواتير**.

## 🛡️ بروتوكول النسخ الاحتياطي للتطوير

قبل أي تعديل على ملف، تُنشأ نسخة احتياطية في مجلد `_backups/` باسم يتضمن **التاريخ والوقت** (`الملف-YYYY-MM-DD_HH-MM`)، مع ملف `MANIFEST` يوثّق سلسلة التعديلات وطريقة الاسترجاع. إن فشل البناء تُسترجع النسخة السابقة.
